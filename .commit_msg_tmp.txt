feat(browser): Agent 自主操作浏览器（Phase 3）

Agent 现在能读用户已打开的页面正文，并能受控操作页面。

新增工具：
- browser_read（Auto）：读当前页正文，返回 status/url/title/content/truncated。
  页面未打开或仍在渲染时返回 no_session/loading，不返回空内容冒充成功。
- browser_act：click/fill/scroll/wait。权限按动作分级——click/fill 改页面状态
  走人工确认闸（无确认器即拒），scroll/wait 不改数据直接执行。

共享会话：
- BrowserSessionHolder 进程级单例。Agent 工具与浏览器页必须操作同一个
  WebView 实例，各建一个的话 Agent 读到的永远是另一个空页面。

修复两个真实缺陷：
- WebView 跨线程调用崩溃：Agent 工具在 runtime 协程里读页面时，
  非主线程调 evaluateJavascript 会抛异常。现在 WebView 调用统一派发到主线程，
  等待留在调用方线程；URL/标题由主线程回调同步进缓存。
- 页面加载失败被当成正常正文：WebView 加载失败时显示的是内部错误页
  （chrome-error://），其正文不是用户要看的内容。现在识别并如实报 error。

实现要点：
- 注入脚本返回对象而非 JSON 字符串：返回字符串会多一层引号转义，宿主解码时
  会把正文里的换行变成裸换行，JSON 直接解析失败。
- 脚本语法错误不会报错，只会让 evaluateJavascript 返回 null，症状与
  "页面没准备好"完全一样。设备端测试逐个跑脚本并断言返回可解析 JSON，
  是唯一能挡住这类错误的自动化防线。
- 填表单用原生 setter 再派发 input/change，React/Vue 的受控组件能收到值。
- 滚动用即时滚动不用平滑滚动：平滑滚动是异步动画，调用返回时还没滚到位。
- 模型给的 selector/文本一律按 JS 规则转义后才拼进脚本。

验证：JVM 单测 426 例（仅 LlmStateMirrorTest 失败，依赖宿主 sh 命令，
Windows 环境问题，改动前即失败）；设备端浏览器相关 25 例全绿，
新增 BrowserSessionShareTest 11 例覆盖共享会话与全部四种动作。
