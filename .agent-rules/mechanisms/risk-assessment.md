# 风险评估

## 结论

项目主要风险集中在 AAOS 模拟器 API 兼容性和车机硬件性能，已制定对应缓解措施。

## 涉及对象

| 层 | 风险项 | 角色 |
|---|---|---|
| System | AAOS 模拟器 | 部分 Car API 可能不可用 |
| System | 车机硬件 | 性能比手机差 2-4 倍 |
| UI | Live2D | 集成复杂度高 |
| System | PTY JNI | 交叉编译配置 |
| Service | EV 电源循环 | 数据丢失风险 |

## 运行链路

### 技术风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| Automotive 模拟器不支持某些 Car API | 高 | 中 | 尽量使用标准 API，备注兼容方案 |
| 车机硬件性能不足 | 中 | 高 | 初期就在低端配置测试 |
| Live2D SDK 集成复杂度高 | 中 | 中 | Phase 1 用 Canvas 代替，Phase 2 再评估 |
| PTY 终端需要额外的 C/JNI 交叉编译配置 | 低 | 低 | NDK 工具链成熟，CMake 配置标准 |
| EV 电源循环导致数据丢失 | 低 | 高 | 每次状态变更都 Checkpoint |

### 开发风险评估

| 风险 | 缓解措施 |
|---|---|
| 缺乏 Kotlin/Android 经验（前端背景） | Jetpack Compose 与 React 理念相似，学习曲线平缓 |
| Automotive 调试困难 | 用好模拟器 + 日志系统 |
| Gradle 构建配置复杂 | 逐步添加依赖，每次验证编译 |

### 性能风险

典型车机硬件指标：
- CPU: 骁龙 660/665 级别（4xA73 + 4xA53）
- RAM: 4-8GB LPDDR4X
- GPU: Adreno 610/650
- 存储: eMMC 5.1，随机读写慢

性能优化优先级：

| 优化项 | 方法 | 优先级 |
|---|---|---|
| 冷启动速度 | App Startup Library + 延迟初始化 | P0 |
| 内存管理 | 避免泄漏、使用 `android:largeHeap` | P0 |
| ANR 预防 | 主线程不做 I/O、协程分离 | P0 |
| UI 帧率 | Compose 性能优化、硬件加速 | P0 |
| 存储优化 | Room DB 批量操作 | P1 |
| 电池优化 | WorkManager 延迟非关键任务 | P1 |

## 使用点

- 每次开发新功能前参考此风险评估
- 性能优化决策参考性能风险表

## 修改点

| 要做什么 | 改哪里 | 怎么改 |
|---|---|---|
| 新增已知风险 | 本文件 | 追加到对应风险表 |
| 风险状态变更 | 本文件 | 更新概率/影响/缓解措施 |

## 关键约束

1. 所有新功能的性能影响必须在典型车机配置上验证。
2. 不引入未经评估的第三方依赖（尤其 Native 库）。
3. 电源循环场景必须做状态持久化。

## 维护方式

- **新增风险**：追加到对应风险表，注明发现时间和上下文。
- **风险解除**：移入"已解除"章节，注明解除原因和时间。
- **审查频率**：每个 Phase 结束时审查一次风险表。
