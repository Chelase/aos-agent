# 语音 B4：唤醒调试面板（真机调命中率的前置）

> **统一愿景对齐**：与 `../../docs/unified-ecosystem-vision.md` 一致。只在本机内存里看判定结果，
> 不落盘、不录音、不上传；音频边界与 B2 完全相同。
>
> 父计划：[../voice-interaction-plan.md](../voice-interaction-plan.md)（Phase B 交付后新增）
> 配套机制文档：`../../mechanisms/voice-interaction.md`

## 为什么先做这个

唤醒链路现在只交一个布尔：命中或没命中。真车上喊十遍"你好Chelsea"没醒，**看不出模型到底听成了什么**
（是 `[unk]`？是"你好切尔西"？还是 KWS 压根没在跑？），改前缀还是换模型全靠猜。
模拟器又没有麦克风，这块只能在真机调——所以调之前必须先把观测做出来，否则到了车上还是盲调。

## 本 Step 范围

| 决策 | 理由 |
|---|---|
| 收集开关默认关，进面板才开、离开就关 | 常驻内存里堆识别文本没必要；调试是显式动作 |
| 只留最近 N 条（20）与两个计数 | 够判断命中率与误唤醒，又不变成日志系统 |
| 原始文本直接显示 | 受限语法下取值只有"选定的说法"或 `[unk]`，**不会漏进日常对话内容**，所以可以安全显示 |
| 放工程师模式，不放设置页 | 这是诊断工具，不是用户配置项 |
| 提供计数复位 | 车上要能"清零→喊 5 次→看命中几个" |

## 改动文件

| 文件 | 动作 |

| `core/voice/WakeDebug.kt` | 新增 — 环形缓冲 + 命中/未命中计数 + `enabled` 开关（纯 Kotlin，可单测） |

## 步骤

### B4.1 采集层
`WakeDebug.record(text, matched)`：`enabled=false` 时直接返回；缓冲满丢最旧；计数只增，`reset()` 清零。
**验收**：单测覆盖"关着不记 / 超上限丢最旧 / 命中与未命中分别计数 / reset 归零"。

### B4.2 引擎埋点
在 `acceptWaveForm` 出结果、算完 `isWake` 之后记一条；**不改变**原有命中判定与冷却。
**验收**：现有 `WakeWordMatcherTest` 与状态机测试零回归。

### B4.3 面板
进入工程师页时 `enabled=true`，离开时 `false` 并 `reset()`（不把现场留在内存里）；
列表用等宽数据行组件，触控目标 ≥56dp。
**验收**：模拟器上（无麦）面板能显示"当前说法 = 你好Chelsea"与"0 条结果"；
`adb shell am broadcast`/灌音频不可行，故"真实命中若干条"标为真机验收项。

## 不可验证项

真车上"喊 5 次命中几次、10 分钟误唤醒几次"必须真机做——本面板就是为那次实测准备的工具，
它本身在模拟器上只能验到"界面与采集开关正确"，验不到"命中数据有意义"。
